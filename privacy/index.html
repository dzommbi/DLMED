Politique de confidentialité

Cette page explique quelles données sont traitées lorsque vous utilisez DLMed, à quelles fins et comment adresser une demande concernant votre compte ou vos données.

1. Gestion du site et contact

DLMed est une plateforme de révision médicale accessible à l’adresse https://dlmed.fyi. Pour toute question ou demande relative aux données personnelles décrites dans cette politique, contactez l’administrateur du site sur Telegram : @Dzombi6.

Évitez d’envoyer par messagerie des mots de passe, des jetons de connexion ou des informations médicales sensibles. Une demande peut nécessiter une vérification raisonnable de l’identité du titulaire du compte.

2. Connexion avec Google et données de compte

La connexion se fait avec Google OAuth, géré par Supabase Auth. DLMed ne vous demande ni ne stocke votre mot de passe Google. Après votre autorisation, Google transmet à Supabase les informations nécessaires à l’authentification. Selon le compte et les autorisations fournies, elles comprennent l’identifiant du compte, l’adresse e-mail et les métadonnées de l’identité Google que Supabase reçoit.

Le code de DLMed utilise l’identifiant Supabase de l’utilisateur pour rattacher le profil et les opérations autorisées à ce compte. L’adresse e-mail et les métadonnées reçues par Supabase Auth ne sont pas recopiées dans la table de profil DLMed. Supabase Auth gère également les informations techniques de connexion et les jetons de session nécessaires pour maintenir la connexion.

La connexion et les données Auth sont traitées par Google et Supabase selon leurs propres politiques : Politique de confidentialité de Google et Politique de confidentialité de Supabase.

3. Nom d’utilisateur

Après la première connexion, DLMed demande un nom d’utilisateur obligatoire afin d’identifier le profil dans l’application. Il doit contenir de 4 à 20 caractères parmi les lettres anglaises, les chiffres et le caractère underscore. Le nom est vérifié pour éviter les doublons, sans distinction entre majuscules et minuscules.

Le profil prévu par le projet Supabase associe ce nom à l’identifiant du compte. Le nom d’utilisateur est utilisé pour retrouver le profil lors des connexions suivantes. La configuration actuelle ne le présente pas comme un profil public consultable par d’autres visiteurs.

4. Gestion des sessions et des appareils

Le code de DLMed prévoit une session active par compte. Il utilise l’identifiant de session fourni par Supabase Auth, un identifiant UUID propre à l’installation du navigateur, ainsi que des horodatages et un état d’activité pour vérifier la session et appliquer la règle du dernier appareil utilisé. L’identifiant d’installation est conservé dans le stockage local du navigateur.

La mise en œuvre côté base de données est définie dans une migration Supabase du projet. La limitation à une session ne peut être considérée comme active que lorsque cette migration et les règles associées ont été appliquées au projet Supabase de production. Lorsque le dispositif est actif, une nouvelle connexion peut invalider l’accès QCM de la session précédente ; le navigateur précédent constate l’invalidation lors de sa prochaine vérification ou reconnexion. Un appareil hors ligne ne peut pas recevoir cette notification immédiatement.

Les sessions d’authentification et leurs jetons sont gérés par Supabase Auth. DLMed utilise les fonctions de base de données et les règles d’accès configurées pour vérifier les opérations sur le compte. Les jetons ne doivent jamais être partagés avec l’administrateur ni avec un tiers.

5. QCM, réponses et stockage local

Les matières, modules, questions, choix de réponse et corrections pédagogiques sont chargés depuis la base Supabase de DLMed. Lorsqu’une réponse est confirmée, le choix sélectionné est transmis au service de correction Supabase afin de retourner le résultat et l’explication.

La progression, les réponses déjà traitées et certaines préférences de révision sont conservées dans le stockage local du navigateur, sur l’appareil utilisé. Le code actuel ne crée pas d’historique nominatif des réponses QCM dans une table Supabase. Ces données locales peuvent être supprimées en effaçant les données du site dans les réglages du navigateur ; cela peut aussi supprimer la session conservée sur cet appareil.

6. Mesure d’audience et cookies

Les pages principales du QCM (index.html et quiz.html) chargent Google Analytics 4. Dans sa configuration par défaut, Google Analytics peut traiter le nombre d’utilisateurs, des statistiques de session, une localisation approximative ainsi que des informations de navigateur et d’appareil. Google Analytics utilise normalement un cookie propriétaire _ga pour distinguer les navigateurs et leurs sessions. Les pages juridiques ajoutées ici ne chargent pas cette balise.

La page d’accueil charge également Cloudflare Web Analytics, qui mesure des indicateurs de performance de page à partir des API de performance du navigateur. Cloudflare indique que cet outil ne collecte ni n’utilise les données personnelles des visiteurs. Cette balise n’est pas ajoutée aux pages juridiques.

Pour en savoir plus : données collectées par Google Analytics et présentation de Cloudflare Web Analytics. Vous pouvez gérer ou supprimer les cookies et données locales depuis les réglages de votre navigateur ; le blocage de certains éléments peut affecter certaines fonctions.

7. Sécurité et conservation

Le site communique avec Supabase via HTTPS et prévoit des règles d’accès en base de données pour limiter les opérations selon l’identité et la session ; leur efficacité dépend des policies requises dans le projet Supabase de production. La configuration du code comprend une clé publique destinée à l’usage navigateur ; aucune clé secrète de service ne doit être publiée dans le site. Ces mesures réduisent certains risques, sans pouvoir garantir une sécurité absolue.

Supabase conserve les données Auth et le profil tant que le compte demeure actif ou jusqu’à leur suppression selon la configuration du projet. Le code ne définit pas une durée chiffrée unique de conservation applicable à toutes les données. La mesure d’audience suit les règles de conservation propres aux services concernés et aux paramètres de leurs comptes.

La disponibilité effective de certaines protections, notamment la session unique et les règles de base de données associées, dépend de la configuration déployée sur Supabase. Cette page décrit le code du projet et signale cette dépendance pour ne pas présenter une protection non activée comme déjà garantie.

8. Vos demandes concernant vos données

Vous pouvez demander à l’administrateur de vous indiquer les données de compte gérées par DLMed, de corriger votre nom d’utilisateur ou de supprimer votre compte et les données de profil qui lui sont associées, sous réserve des contraintes techniques et des obligations applicables. Il n’existe pas de fonction libre-service de suppression de compte dans l’interface actuelle : adressez votre demande à @Dzombi6 sur Telegram.

Vous pouvez aussi supprimer les données de progression locales depuis votre navigateur. La suppression de l’application ou de ses données locales n’efface pas à elle seule le compte Supabase ; contactez l’administrateur pour une demande de suppression de compte.

Cette politique peut être mise à jour si les traitements de DLMed évoluent. La date affichée en haut indique la dernière mise à jour publiée.
